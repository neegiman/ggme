# 셋의 비밀 · GGME

같은 자리에 모인 성인 **3~8명**이 각자의 휴대폰으로 비밀 카드를 확인하고 대화하는 정적 웹게임입니다. 라이어·스파이·금지어 게임을 제공합니다. HTML5, CSS3, Vanilla JavaScript만 사용하며 프레임워크·백엔드·DB·WebSocket·외부 CDN이 없습니다.

> **임시 규칙 v1**: `three_player_web_games_design_v1.md` 원문이 작업 환경에 없어 [명시한 규칙](docs/RULES.md)을 적용했습니다. 원문과의 일치는 미검증입니다. 인원 확장 시 단독 최다 득표자를 지목하고, 최다 득표가 동률이면 라이어·스파이가 승리하도록 일반화했습니다.

## 디자인

옛 CMD 창을 모티브로 검은 배경, 녹색 글자, 시스템 고정폭 글꼴, 각진 테두리와 `C:\GGME>` 프롬프트를 사용합니다. 생성자·개인 카드·타이머·판정·결과·모달에 같은 테마를 적용합니다. 외부 폰트와 이미지는 사용하지 않습니다.

## 시대별 단어

라이어·금지어에서 **60·70·80·90·00년대**를 고르거나 **모두 섞기**로 플레이합니다. 시대별 12개, 총 60개이며 기본 선택은 모두 섞기입니다. 다음 라운드 설정에서 게임과 단어 묶음을 바꿀 수 있습니다. 스파이는 장소·직업을 사용합니다.

60~00은 **1960~2000년대 사용·문화 시기**를 뜻하며 출생 세대 구분은 아닙니다. 60~80년대는 당시 시대어·추억말, 90·00년대는 통신·인터넷 표현을 중심으로 편집했습니다. 국립국어원의 공식 세대 분류, 최초 유행 연도, 특정 세대의 독점적 이해를 뜻하지 않습니다. 자료의 조사 구간이 여러 연대에 걸치는 경우도 있습니다.

국립국어원 『광복 70주년 학술 자료집』, 1999년 「컴퓨터 대화방의 언어」, 2005년 『새국어생활』 등을 참고했습니다. 역사박물관·한국학중앙연구원 자료로 문화 맥락을 보완했습니다. [단어별 뜻·출처·선정 기준](docs/WORD_SOURCES.md)을 확인하세요. 앱의 **단어 자료·선정 기준 보기**에서도 원문 링크를 제공합니다.

라운드를 완료하면 이번 판 단어의 뜻과 출처가 생성자 결과 화면에 나타납니다. 진행 중에는 뜻풀이 목록을 표시하지 않으며 개인 링크에는 기존 허용 정보만 넣습니다. 자료와 단어는 앱에 포함돼 실행 중 API·CDN 요청이 없습니다. 참고 자료 링크는 사용자가 직접 열 때만 해당 사이트로 이동합니다.

기존 일상·음식·취미 라이어 묶음과 금지어의 기본 대화어를 계속 사용할 수 있습니다. 이전 라운드·개인 카드·통산 점수의 형식도 유지합니다.

## 실행

Node.js 22 이상, 앱 의존성 설치 불필요:

```powershell
npm run dev
```

`http://127.0.0.1:4173/ggme/`를 여세요. 상위 작업 폴더에서 실행한다면 먼저 `cd three-player-games`를 실행하세요. ES Modules를 사용하므로 `file://` 더블 클릭 실행은 지원하지 않습니다. 개발 서버는 정적 파일 미리보기 전용입니다.

같은 Wi-Fi의 휴대폰에서 테스트하려면:

```powershell
npm run dev -- --host 0.0.0.0
ipconfig
```

생성자와 참가자 모두 컴퓨터 IPv4 주소를 사용하세요. 예: `http://192.168.0.10:4173/ggme/`. `localhost`에서 생성한 초대 링크는 다른 기기에서 열리지 않습니다. 공유·클립보드 API는 HTTPS 배포에서 사용하는 것이 좋으며, 미지원 시 수동 복사 기능이 제공됩니다.

## 플레이

1. 생성자가 게임, 인원 3~8명, 서로 다른 이름, 대화 시간을 선택합니다. 라이어·금지어는 시대별 또는 기본 단어도 선택합니다. 생성자도 참가할 수 있습니다.
2. 초대 화면에서 한 명씩 **이전·다음**으로 넘깁니다. 해당 참가자에게만 **개인 QR**을 보여 주거나 링크를 복사·공유합니다. QR이 작으면 **QR 크게 보기**를 누르세요. 참가자는 본인 휴대폰 카메라로 스캔하고 이름·라운드 번호를 확인한 뒤 카드를 엽니다.
3. 생성자가 카드 확인 여부를 직접 듣고 참가자별 확인 체크를 선택합니다. 자동 접속 확인이 아닙니다.
4. 대화 중 타이머를 시작·일시정지·초기화합니다. 시간 종료 후에도 생성자가 직접 판정합니다.
5. 라이어·스파이는 각자의 투표, 금지어는 합의한 위반 횟수를 생성자가 입력합니다. 결과 저장 시 점수를 한 번만 반영합니다.
6. 다음 라운드는 통산 점수를 유지하며 새로운 배정·라운드 ID·개인 링크를 만듭니다. 참가자 전원에게 새 링크를 전달하세요.
7. 새 멤버 게임은 점수를 초기화하고 완료된 기록을 보관합니다. 기록은 JSON으로 내보낼 수 있습니다.

라이어·스파이는 인원과 관계없이 특수 역할 1명과 시민 N−1명입니다. 금지어 카드에는 다른 N−1명의 단어만 표시합니다. 역할과 단어는 독립 추첨하므로 이전과 같은 배정이 나올 수 있습니다. 스파이의 시민 직업은 장소에 맞게 배정하며 중복될 수 있습니다.

## GitHub Pages 배포

목표 주소: **https://neegiman.github.io/ggme/**. 저장소: **https://github.com/neegiman/ggme**.

이 폴더의 내용을 `ggme` 저장소 최상위에 커밋·푸시합니다. GitHub **Settings → Pages → Deploy from a branch → main → /(root)** 를 선택하면 빌드 없이 배포할 수 있습니다. `index.html`, `card.html`, `css/`, `js/`, `favicon.svg`, `.nojekyll`의 구조를 유지하세요. 상대 경로를 사용하므로 `/ggme/` 하위 경로에서 개인 링크와 자원이 정상 작동합니다. `/ggme`는 GitHub Pages가 `/ggme/`로 이동합니다.

배포용 파일만 별도로 복사하려면:

```powershell
npm run build
```

`dist/`에 HTML·CSS·JavaScript·SVG·.nojekyll만 복사합니다. 공유 사이트의 하위 폴더로 배포할 때는 이 내용을 해당 사이트의 `ggme/`에 복사하세요. 예를 들어 저장소 `home`의 `ggme/`라면 공개 주소는 `/home/ggme/`입니다. 빌드 결과를 다시 `ggme/ggme/`로 중첩하지 마세요.

GitHub Actions로 정적 배포하는 경우에는 제공된 상위 작업 폴더 `.github/workflows/three-player-pages.yml`이 원래의 `three-player-games/` 구조를 대상으로 합니다. `ggme` 단독 저장소는 위 브랜치 배포를 사용합니다. [GitHub Pages 공식 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)를 참고하세요.

## 테스트

```powershell
npm test
```

Node.js 내장 러너로 3~8명의 점수·투표·정답 추측·금지어·개인 데이터 허용 목록·링크·저장소·이전 버전 호환을 검사합니다. 모든 3인 투표 조합, 각 인원별 모든 특수 역할 자리, 단독 최다 득표·동률·오지목·자기 투표 거부를 포함합니다. QR은 독립 디코더로 원래 개인 URL과 정확히 일치하는지 검사하며, 8명 모두 최대 길이 이모지 이름인 금지어 카드도 포함합니다.

브라우저 통합 검증은 개발용 Playwright만 추가로 필요합니다. 배포에는 포함되지 않습니다.

```powershell
npm install --no-save playwright
npx playwright install chromium webkit
npm run test:browser
```

이미 설치된 모듈은 `PLAYWRIGHT_MODULE` 환경 변수로 지정할 수 있습니다. 테스트는 임시 포트의 정적 서버를 자동 시작·종료합니다. `/ggme/`에서 Chromium·WebKit의 생성·개인 카드·타이머·판정·점수 저장·복원·다음 라운드·내보내기를 검증합니다. 한 명씩 초대 탐색, 화면에 그려진 QR 디코딩, 확대·닫기, 수동 체크 유지도 확인합니다. 실제 메시지 전송 없이 공유 API를 모의 검증하며 Chromium은 클립보드 복사도 확인합니다. 가로 넘침·44px 터치 영역·콘솔 오류·외부 요청을 검사합니다.

결과 JSON과 Chromium 캡처는 Git에서 제외되는 `test-artifacts/`에 생성합니다. WebKit은 Playwright 캡처의 인라인 스타일 삽입이 CSP에 차단되어 기능과 DOM 레이아웃을 검사합니다. 실제 iPhone·Android와 네이티브 공유 시트 전송은 미검증입니다. [검증 범위](docs/VERIFICATION.md)를 참고하세요.

## 데이터와 정적 구조

**실시간 동기화는 없습니다.** 참가자 접속·카드 확인·타이머·투표·결과는 기기 간 자동 공유되지 않습니다. 생성자 화면 하나를 기준으로 수동 진행합니다. 같은 브라우저 내 생성자 탭의 localStorage 갱신은 반영하지만 기기 간 동기화는 아닙니다.

개인 URL은 `card.html#<Base64URL JSON>`입니다. 해당 참가자에게 허용된 정보만 명시적으로 추출합니다.

| 카드 | 비밀 정보 |
| --- | --- |
| 라이어 | 자기 역할·카테고리 |
| 시민 (라이어 게임) | 자기 역할·카테고리·공통 단어 |
| 스파이 | 자기 역할 |
| 시민 (스파이 게임) | 자기 역할·장소·자기 직업 |
| 금지어 | 다른 N−1명의 이름·금지어, 자기 단어 배정 제외 |

공통 메타데이터는 버전·인원·라운드 ID·번호·게임·본인 이름·좌석입니다. 전체 배정·다른 역할 목록·난수 seed·통산 점수는 개인 링크에 넣지 않습니다. 개인 카드 페이지는 생성자 저장소나 단어 배정 모듈을 불러오지 않습니다.

QR에는 동일한 개인 URL만 담습니다. 초대 화면에는 현재 한 사람의 링크와 QR만 렌더링하며, 확대 창을 닫으면 그 QR도 제거합니다. QR 생성은 저장소에 포함된 로컬 코드로 처리하며 외부 이미지 서비스로 링크를 전송하지 않습니다. 스캔이나 확대가 전달 완료로 자동 처리되지는 않습니다. 모든 참가자가 확인했다고 알려 주면 생성자가 직접 체크하고 시작합니다. QR 용량 초과·생성 실패 시 링크 복사·공유로 계속 진행할 수 있습니다.

Base64URL은 암호화·인증이 아닙니다. 링크를 가진 사람은 내용을 읽거나 바꿀 수 있으며 이전 링크를 회수·만료시킬 수 없습니다. 생성자 localStorage에는 판정에 필요한 전체 배정이 저장됩니다. 정직한 진행을 전제로 합니다.

입력을 검증하고 HTML에 표시할 때 이스케이프합니다. CSP는 외부 연결과 인라인 스크립트·스타일을 차단합니다. 비밀 카드 숨김 시 DOM에서 비밀을 제거하며 앱 전환·창 비활성화·페이지 이동 시 자동으로 숨깁니다. 화면 보호 기능은 URL 내용 자체를 암호화하지 않습니다.

저장 키 `three-of-us:local:v1`은 유지합니다. 저장 스키마 v2와 개인 카드 v2를 사용하며 기존 3인용 저장 스키마 v1·카드 v1을 읽습니다. 현재 그룹 최근 50라운드, 이전 그룹 최대 200라운드를 보관합니다. 도메인·브라우저가 달라지거나 사이트 데이터를 삭제하면 복원되지 않습니다. 저장 차단·용량 초과 시 현재 탭에서 진행하면서 저장 실패를 표시합니다. 완료 기록의 JSON에는 해당 라운드 비밀도 포함됩니다.

## 구성

- `index.html`, `js/app.js`: 생성·초대·수동 진행·결과
- `card.html`, `js/card.js`: 독립된 개인 카드
- `css/style.css`: 디자인 토큰·반응형 UI
- `js/core.js`: 순수 판정·점수·이름 검증·시간
- `js/round.js`, `js/links.js`: 배정·개인 정보 추출·URL 검증
- `js/qr.js`, `js/vendor/`: 로컬 QR 생성·SVG 표시 ([qrcode-generator 2.0.4](js/vendor/README.md), MIT)
- `js/storage.js`: 저장·복원·이전 기록 변환
- `js/data.js`, `js/ui.js`: 로컬 단어·장소·SVG·이스케이프
- `tests/`, `scripts/`, `docs/`: 테스트·개발 도구·규칙·검증 기록

테스트 전용 독립 QR 디코더는 [jsQR](tests/vendor/README.md) (Apache-2.0)이며 앱에서 불러오지 않고 배포 빌드에서도 제외합니다. 각 원본 라이선스와 고정 커밋을 해당 폴더에 보관합니다.
