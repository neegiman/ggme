- 3~8명 각각 세 게임의 역할·허용 데이터·고유 개인 링크·다음 라운드 재발급 및 저장 복원을 검사했습니다. 확장된 무작위 카드 검증 180라운드와 기존 90라운드를 포함합니다.
- 이전 카드 v1과 저장 스키마 v1을 읽고 3인 점수·완료 기록·라운드 ID를 유지하는 것을 확인했습니다.
- Chromium·WebKit의 **3명 및 8명** 전체 흐름: 생성 → 서로 저장소를 공유하지 않는 참가자 컨텍스트의 모든 카드 → 표시·숨김 → 전달 체크 → 타이머 → 수동 판정 → 결과 → 새로고침 → JSON 내보내기 → 다음 라운드 → 새 멤버.
- 실제 클립보드 복사는 Chromium에서 검사했습니다. 공유는 실제 메시지를 보내지 않고 모의 API의 개인 URL을 검사했습니다.
- `/ggme/`에서 링크가 `/ggme/card.html#…`로 생성되는 것을 검사했습니다.
- 시작 화면 320/360/390/430/768/1280px, 진행·카드 화면 320/390/430px에서 가로 넘침과 44px 터치 영역을 검사했습니다. 최대 길이 한글·영문·이모지 이름도 확인했습니다.
- 숨김 시 비밀 DOM 제거, 앱 전환 이벤트, 자기 단어 배정 미포함, 스파이 장소·라이어 단어 미노출을 확인했습니다.
- 타이머 일시정지·시간 경과·새로고침·초기화, 누락 투표·자기 투표·중복 이름·링크 손상·XSS 텍스트·저장소 손상/차단·점수 중복 방지를 검사했습니다.

기계 판독 결과와 Chromium 화면은 `test-artifacts/report.json`, `test-artifacts/*.png`에 생성하며 Git 및 배포에서 제외합니다. `npm test`, `npm run test:browser`로 재현할 수 있습니다.

## 한계

첨부 설계서 원문 대조와 실제 iPhone Safari·Android Chrome 기기 검증은 미완료입니다. 모바일 엔진 에뮬레이션은 물리 기기를 대체하지 않습니다. 실제 참가 기기들로 공유 시트·키보드·앱 전환·링크 재전달을 확인해야 합니다.

WebKit의 Playwright 화면 캡처는 인라인 스타일 삽입 때문에 CSP에 차단됩니다. CSP를 유지하면서 WebKit 기능·DOM 레이아웃을 검사하고 픽셀 캡처는 Chromium에서 수행합니다.

GitHub Pages 공개 배포 성공: https://neegiman.github.io/ggme/ (HTTPS). 저장소: https://github.com/neegiman/ggme. GitHub Actions의 Game logic tests 및 pages build and deployment가 성공했습니다. 공개 주소에서 Chromium 통합 테스트를 다시 실행하여 3명·8명 전체 카드 흐름과 3~8명 전체 생성자 흐름이 통과했고 콘솔 오류·외부 요청은 0이었습니다.

추가 검증: Chromium·WebKit 모두 4/5/6/7명으로 세 게임을 연속 진행하며 단독 최고 득표 동률 처리·결과·다음 게임·통산 기록을 확인했습니다. 인원 선택을 줄였다 늘려도 입력한 이름이 유지되고 새 그룹에서는 인원 선택이 유지됩니다. 최종 브라우저 콘솔 오류 0, 외부 요청 0입니다.

## 개인 QR·한 명씩 전달

- QR 관련 자동 테스트 9개를 추가해 총 37개가 통과했습니다. 독립 구현인 jsQR로 세 게임의 3명·8명 개인 QR을 디코딩하고 원래 개인 URL 및 허용 데이터와 정확히 일치하는지 확인했습니다.
- 초대 화면은 현재 참가자 한 명의 링크·QR만 렌더링합니다. 이전·다음 경계, 참가자 이름·순번, 현재 참가자의 복사·공유, 확대 창 닫기 후 이전 QR 제거를 검사했습니다.
- 스캔·확대·이동은 전달 체크를 자동 변경하지 않습니다. 체크는 이동·새로고침 후 유지되며 전원 수동 확인 전에는 시작이 차단됩니다. 새 라운드는 새 링크와 미확인 상태로 시작합니다.
- Chromium·WebKit에서 실제 SVG를 화면 표시 크기로 래스터화하고 독립 디코더로 읽었습니다. 모든 게임의 3명·8명 QR 및 확대 QR, 최대 길이 이모지 이름 8명이 참여하는 금지어 QR을 포함합니다. 전체 생성·카드·타이머·판정·저장 흐름도 통과했습니다.
- 작은 화면에서 조밀한 QR이 부분 픽셀 크기로 표시되면 읽기 실패가 발생할 수 있어 모듈을 화면 픽셀의 정수 배수로 맞췄습니다. 화면 크기 변경 시 다시 계산합니다. 별도 검증에서 두 엔진 모두 화면 배율 1·2·3, 320/390/430/768/1280px에서 최대 길이 이름의 개인 QR 8개 및 확대 QR을 읽었습니다.
- 320/390/430px의 초대·확대 화면에 가로 넘침이 없고 터치 영역은 44px 이상입니다. QR 생성·표시 때문에 외부 요청이 발생하지 않습니다. QR 인코더는 앱에, 독립 디코더는 테스트에만 포함되며 원본 라이선스를 보관합니다.

이는 브라우저·이미지 디코더 검증이며 실제 휴대폰 카메라로 다른 화면을 촬영하는 검증은 수행하지 않았습니다.

## 시대별 단어

- 1960~2020년대 일곱 시대 각 30개, 총 210개와 모두 섞기 묶음입니다. 뜻·출처가 모두 연결되어 있고, 각 묶음은 8명에게 서로 다른 금지어를 배정할 수 있습니다. [자료와 편집 기준](WORD_SOURCES.md)을 별도로 기록했습니다.
- Node.js는 여섯 묶음 × 인원 3~8명 × 라이어·금지어에서 선택한 묶음 내 배정, 비밀 정보 허용 목록, 금지어 중복 방지, 개인 URL 인코딩을 반복 검사합니다. 뜻과 출처가 개인 URL에 추가되지 않는 것도 검사합니다.
- 일곱 시대와 모두 섞기의 완료 결과 저장·복원, 묶음을 바꾼 새 라운드의 링크 재발급·통산 점수 유지, 기존 카테고리와 스파이 장소 목록 유지도 검사합니다.
- 가장 긴 시대별 단어와 최대 길이 이모지 이름 8명의 개인 URL을 QR로 만들고 독립 디코더로 읽었습니다.
- 브라우저 검증은 일곱 시대 × 라이어·금지어를 포함합니다. 선택한 묶음의 실제 배정 → 새로고침 → 수동 판정 → 결과의 뜻·원문 링크 → 다시 새로고침 → 다음 게임·묶음 변경을 검사합니다.
- 진행·판정 화면에는 뜻풀이 목록이 없고 결과에만 나타나는지 확인합니다. 320/390/430px에서 단어 자료 창과 결과 화면의 가로 넘침·44px 터치 영역을 검사합니다.
- 시작 전 단어 설명·선정 기준 창에 전체 210개 중 어느 정답 후보도 포함되지 않는지 검사합니다. 상세 참고 문헌은 시작 전에는 숨기고 완료 결과에서만 나타나는지 확인합니다. 우리말샘 개별 링크는 게임에 쓰는 동음이의어의 뜻을 가리키는지 자료 조사에서 확인했습니다.


## 참가자 입력을 응답 QR로 가져오기 · v0.5.0

- Node 테스트 12개를 추가했습니다. 공개 이름 목록·본인 응답 키만 담는 카드 v3, 응답 허용 목록·코덱·다른 라운드/키/좌석/권한 거부·중복 및 이전 응답 재스캔 방지·저장 복원·키 변경·QR 용량을 검사합니다. 기존 43개와 함께 55개가 통과했습니다.
- Chromium·WebKit에서 3명·8명 라이어·스파이의 개인 입력 → 화면 QR 디코딩 → 생성자 이미지·응답 코드 가져오기 → 수동 확정 → 점수 저장 → 복원 → 다음 라운드를 검사했습니다. QR 가져오기만으로 점수가 반영되지 않습니다.
- 카메라 권한 거절 후 이미지·코드 입력, 초대 QR/다른 라운드 거부, 이미 읽은 응답, 최신 입력 및 직접 수정 보존, 기존 카드 v2, 시민 오지목 시 즉시 라이어 승리를 확인했습니다.
- Chromium에서는 QR 영상을 그린 canvas.captureStream()을 카메라 대신 주입해 영상 디코딩과 오디오 미사용, 창 닫기 후 트랙 종료, 늦게 승인된 스트림 종료를 확인했습니다. 이는 실제 기기의 카메라 권한·초점·화면 촬영 검증이 아닙니다. WebKit에서는 권한 거절 모의 및 이미지·코드 경로를 확인했습니다.
- 320/390/430px 응답 화면·읽기 창의 가로 넘침과 44px 터치 영역, QR 픽셀 정렬, 비밀 카드와 QR의 동시 노출 방지·창 비활성화 시 숨김을 확인했습니다. Chromium 캡처를 육안 확인했습니다.
- 기존 세 게임·3~8명·일곱 시대별 단어의 Chromium·WebKit 전체 통합 테스트도 통과했습니다. 브라우저 오류·외부 요청은 0입니다. 재현: npm test, npm run test:browser, npm run test:responses.
- 판독기는 앱에 포함한 jsQR (Apache-2.0)입니다. 영상·이미지는 로컬 처리하며 외부 업로드가 없습니다. 새 라운드에만 응답 키를 추가해 기존 링크·진행 중 저장 데이터의 수동 입력을 유지합니다.
